Plan 04-01 holds the phase-level audit and FA-1 to FA-11.

- FA-1 (the boundary list is planned, not observed): the file lists the boundaries the spec will take; a row that stops early simply has fewer of them on disk, and the reader accepts any prefix of the plan in order. A folder that is not in the plan at all is the error.
- FA-2 (a mode is invisible to the manifests): `pc_manifest.tree_manifest` holds no mode, so a chmod never shows in a snapshot diff or a git status; the restriction is therefore proven by `perms.txt` at the restriction boundary and by the model's tool result in the trace, and restoring the mode cannot be mistaken for a write.
- FA-3 (an accepted residual, stated): a harness process killed between the hook and the finalizer leaves one scratch file at mode 444 inside the run root; the owner can change it back, nothing outside the run root is affected, and the harness never deletes it.
</flagged_assumptions>

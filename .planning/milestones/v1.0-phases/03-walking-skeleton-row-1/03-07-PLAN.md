The planner planted a clean-filter driver in a scratch repository's .git/config, selected it with an attributes file and changed the modification time of a tracked file; plain git status, and git status with both options set to false, ran the driver's command. - FA-3 (what counts as write-capable): the programs bash_mentions already labels (python3 -c, awk, sed with in-place or a w command, find with an output flag or -exec, git with --output, mkdir, tee, cp, mv, dd, touch, install), plus an output redirection (greater-than forms, append, force, ampersand forms) because a read-only program with a redirection writes; descriptor duplications (2>&1, >&2) and /dev/null, /dev/stdout and /dev/stderr are not paths. This is the planner's reading of the verification's wording ("an executed write-capable program") and the review's sketch, widened by the redirection form only.
- FA-4 (what names a path): plain words of the part after the program name, with the script argument left out; the value after an equals sign in an option or assignment form (--output=PATH, of=PATH, an awk -v name=PATH); the target of a redirection; and path-like quoted literals inside a script. A script body is never judged as a path: the script argument of awk, sed, python3 -c and perl, ruby or node -e is excluded from the plain-word check, so a regular expression such as /^## /, a bare slash and a split separator never count. Two things are read from a script and nothing else: a quoted string literal that looks like a path (no whitespace, and either a slash followed by a character that is not a slash, a tilde, $HOME or ${HOME}, or a dot-dot segment together with a slash), and, for sed only, the file operand of a w or W command or of the w flag of an s command, because that operand is the path a write verb names (the one narrow exception to the exclusion, judged by the same path-like test; remove it and the sed w row of the escape table if the exception is not wanted). A leading run of NAME=value words and an env prefix (with the values of its -u, -C and -S options) never hides the program. A script is not parsed further. Absolute paths are compared by realpath with the realpath of each approved root; relative paths are inside unless they hold a dot-dot segment. A cd earlier in the same command whose argument escapes (or a bare cd) makes every later write-capable part of that command escaping. A working directory kept between separate Bash calls is not modeled (the binary resets a working directory that leaves the project).
- FA-5 (false-positive cost): a breach ends the row with exit 11 after the money is spent and the destination name is not consumed but a retry needs bokiko's word. The rule is therefore tabled both ways in the tests: every escaping shape above, and the read-only and inside-the-roots shapes the real baseline used (ls, cat, wc, shasum, head, git status, find -name, sed -n with a print script, awk with a print script and a regular expression, pwd, date, mkdir and python3 -c inside the project).

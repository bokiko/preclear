Because a write-capable part is an escape only when it names an outside place, the list matters only for programs that legitimately name outside places; that is why the list is short and the rule is open-world.
- FA-4 (what is judged in a write-capable part, and the cases that stay conservative): plain words go through _escapes as today. A word that holds whitespace (a sh -c string, interpreter code) is cut on whitespace, and every quoted literal inside a word is cut on whitespace and on quote, bracket, comma, semicolon and equals characters; each resulting token that reads as a path (the existing _path_like gate: no whitespace, a slash followed by a non-slash, a tilde, HOME, or a dot-dot segment with a slash) goes through _escapes. The program-text word of awk and sed is the one exception to the whitespace cut (an awk regular expression such as /^## / is never cut), so only its quoted literals and, for sed, its w operands are judged. The sed w operand is read with zero or more spaces after the w, with the w at the start of the script or after a semicolon, a brace, a space, a digit address or the slash of an address, and counts only when it is path-like and longer than two characters, so the flag in sed -n '/w/p' is not an operand. Known conservative cases, named in tests and README: an interpreter command that only reads an outside path, and a regular expression literal in interpreter code that reads as an absolute path, are counted (the 03-07 FA-5 cases), because an interpreter cannot be shown read-only.
- FA-5 (shell grammar, Task 2): a command substitution, a backquote pair and a process substitution are parsed as commands of their own, outside single quotes and inside double quotes, because a read-only program with a substitution argument would otherwise hide a write. A heredoc body is cut out before the command is split (WR-02), but only a quoted-delimiter body (any quoting of the delimiter: single quotes, double quotes or a backslash) is pure data; the body of an unquoted-delimiter heredoc is scanned for command substitutions and backquote pairs, whose bodies are queued as commands, because the shell expands them. An unquoted hash that starts a word is a comment to the end of the line: it is dropped before the command is split and an apostrophe in it never opens a quote. The reserved words if, then, elif, else, while, until, do, the exclamation mark and the opening brace are skipped and the next word is the program; fi, done, esac, in, the closing brace and the closing double bracket stand alone and decide nothing; the double opening bracket is read like the single one; the header of for, select and case (for NAME in WORDS, case WORD in) is data, not a program, which refines the orchestrator's "next word is the program" for those three words, because the next word there is a loop variable. The heredoc, comment, reserved-word and substitution handling sits only in bash_mentions; git_mutations, helper_calls and first_status_text keep reading the command as they do today. A nesting depth over four makes the command unparsed.
- FA-6 (labels, mktemp, script-program options): the labels of 03-07 are kept for the forms that had them (python3-c, awk, sed-write, find-output, git-diff-output, redirect and the program name of the old closed list).

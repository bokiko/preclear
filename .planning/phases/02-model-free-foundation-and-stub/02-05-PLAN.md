- FA-3 (promote destination): promote accepts any new path under tests/evidence of the repository root it is given (tests pass a temporary root); naming the dated evidence folder and per-row file set is Phase 3 (EVID-04).
- FA-4 (file size cap): MAX_FILE_BYTES is 5 MiB, enough for a sanitised transcript and far above any checkpoint; above it a file is refused, never skipped. The rules reuse the linear-shaped gitleaks patterns, so catastrophic backtracking is not expected; the cap is the second guard.
- FA-5 (scanner scope): the gate scans file names and file contents as text. It does not decode archives or images; a binary file is refused (NUL bytes) rather than scanned.
- FA-6 (probe items owned here): EVID-02 adjacency, empty, encoding, ordering and EVID-03 adjacency, empty, ordering, concurrency are explicit truths above, with two backstops for limits that cannot be exercised on this machine.
- FA-7 (dependencies): this plan imports pc_exitcodes (plan 02-01) for codes 14, 15 and 17, pc_runroot helpers (plan 02-03) for exclusive creation, and pc_testutil (plan 02-01) for temporary-directory helpers; it creates pc_seeds, which later plans reuse.

<flagged_assumptions>
Plan 04-01 holds the phase-level audit and FA-1 to FA-11; plan 04-06 holds the chain items.

- FA-1 (an engineering choice, stated): the analysis mechanism (`RowSpec.analyses`, `pc_review.ANALYSES`) is introduced here for row 7 and reused by rows 10 and 11 and the layouts; an analysis returns a section for `mechanical-checks.md` and extra flat files for the row folder, and runs only for a completed chain (a stopped row has no printed checkpoint to pair).
- FA-2 (the token rules are the research's recommendation plus one correction found while planning, D-06 discretion): the committed row 7 full trace shows the model reproducing its own checkpoint inside a refused Write and a byte-measuring heredoc, which would pair every entry with that call; calls that reproduce the checkpoint are therefore excluded and counted. Otherwise: entry tokens and call tokens are whole tokens so a substring match cannot pair every entry with every call; if the first real triple shows the rules pair too little or too much, the next plan revision changes the rules and the table is rebuilt from the filed files, because the table is a pure function of filed text.
- FA-3 (D-07 location): `row7-review.md` sits at the top level of the folder that holds the attempts; for the triple that is the triple's own labelled dated folder (plan 04-17), and the clean-clone baseline's README points to it by name when the clone holds it.
</flagged_assumptions>

<objective>
Build the Do-not-redo review: parse each printed checkpoint's Do-not-redo entries, list for every entry the tool_use ids of the same `/preclear` turn that share a path or an exact token with it, mark an entry with no candidate UNSUPPORTED, file the per-attempt candidates and the row 7 facts with each completed row 7 chain, and build the single top-level `row7-review.md` that shows the attempts side by side with failed attempts kept.

Purpose: RERUN-01 and D-06, D-07: row 7's defect must be visible in a table, not hidden, and the harness must never decide.
Output: `pc_review.py`, the analysis hook in `pc_evidence.py`, the `row7-review` subcommand in `pc_baseline.py`, `test_review.py`, an updated vocabulary scan and README lines.
</objective>
